# MadDragon

- 문서 유형: 게임
- 문서 버전: 1.0
- 프로젝트 버전: v0.6.2 (portable exe 파일명 기준)
- 근거 신뢰도: low-medium: 파일 존재/경로는 확인됨(high), 문서 본문 내용은 이번 세션에서 열람 불가(low) — 하기 섹션 중 사실 확인 불가 항목은 [제안]으로 표기

## 1. 문서 메타데이터와 근거 범례

- [사실] 근거는 파일 경로/파일명 존재 여부로 한정되며, 문서 본문(`MadDragon_기획서.md` 등)은 이번 세션에서 열람 권한이 차단되어 내용 확인 불가.
- [사실] 범례: [사실]=경로/파일 존재로 확인, [제안]=파일명·구조로부터의 추정 또는 향후 검증 필요 가설.
- 본 문서의 수치, 페르소나, KPI, UI 상태 등 세부 항목은 별도 표기가 없는 한 모두 [제안]이며, 향후 `기획서.md` 본문 열람 후 갱신 필요.

## 2. 문제 정의

- [제안] 타워/유닛 방어 전략 장르에서, 짧은 세션(모바일 이동 중) 동안 전략적 의사결정(스킬/버프 배치)을 내리기 어려운 UX 문제를 다룰 가능성이 있음(`maddragon-mobile-loop` 워크트리명 근거).
- [제안] `TestBuffBuildingAI`, `TestMageTowerAI` 존재는 타워/건물 AI의 버프·마법 상호작용이 핵심 검증 대상임을 시사.
- 실제 문제 정의 문장은 `기획서.md` 본문 확인 후 구체화 필요.

## 3. 한 줄 피치와 제품 포지셔닝

[제안] "플레이어는 유닛과 타워를 배치해 마법사 타워의 버프를 활용, 짧은 전투를 반복 승리로 이끄는 모바일 전략 디펜스 게임." (파일명 `TestMageTowerAI`, `TestBuffBuildingAI`, `TestSimpleUnitAI` 조합에 근거한 추정 피치이며 원문 확인 필요).

## 4. 주 페르소나

[제안] 이수민, 29세, 사무직 회사원, 출퇴근 지하철에서 5~10분 단위로 모바일 전략 게임을 플레이하며 복잡한 조작보다 빠른 의사결정과 즉각적 피드백을 선호. `maddragon-mobile-loop` 워크트리명에서 모바일 세션 최적화가 진행 중임을 근거로 설정한 가상 페르소나이며, 실제 페르소나 정의는 `persona_playtest_feedback.md` 원문 확인 후 교체 필요.

## 5. 디자인 기둥과 핵심 재미

- [제안] 유닛 배치(SimpleUnitAI) + 타워 방어(MageTowerAI) + 버프 건물(BuffBuildingAI) 조합에서 나오는 시너지 설계.
- [제안] 짧은 전투(TestBattle 씬 1개 확인)를 중심으로 한 반복 가능한 소규모 전투 루프.
- 핵심 재미 요소의 구체 서술은 원문 미확인으로 추가 검증 필요.

## 6. 핵심 루프

유저가 선택을 하면 결과가 되고, 그 결과 때문에 다시 선택을 한다.

플레이어는 유닛과 타워를 배치한다 → 버프 건물이 인접 유닛/타워를 강화한다 → 적이 접근해 전투가 발생한다 → 전투 결과에 따라 자원/보상을 획득한다 → 획득한 자원으로 다시 배치를 강화한다. (씬/스크립트 파일명 조합에 근거한 [제안] 순환 문장이며 원문 대조 필요)

## 7. 최초 30초 플레이 흐름

- [제안] 0~5초: 05_TestBattle 유사 전투 씬 로드, 초기 유닛 배치 UI 노출.
- [제안] 5~15초: 플레이어가 첫 유닛/타워 1~2개 배치.
- [제안] 15~30초: 첫 적 웨이브 접근, 버프 건물 효과 첫 발동.
- 실제 튜토리얼 흐름은 원문 미확인.

## 8. 게임 규칙과 승패 조건

[제안] 방어 대상(기지/타워)이 파괴되면 패배, 웨이브(들)를 방어하면 승리하는 전형적 타워 디펜스형 규칙으로 추정. `TestMageTowerAI`, `TestBuffBuildingAI`, `TestSimpleUnitAI` 세 종류 AI 스크립트가 각각 방어 유닛, 마법 타워, 버프 건물의 개별 행동 규칙을 담당함을 시사하나, 정확한 승패 조건 수치는 원문 확인 필요.

## 9. 콘텐츠, 진행, 성장, 경제 구조

[제안] SimpleNaturePack(자연 배경 에셋)과 ToonyTinyPeople(캐릭터 에셋)을 활용한 스테이지형 콘텐츠 구조 추정. 성장/경제 시스템(재화, 강화 등)의 구체 내용은 원문 미확인.

## 10. MVP 가설과 검증 방법

- 가설 1: 버프 건물(BuffBuildingAI)의 존재가 유닛 단독 배치 대비 전투 승률을 유의미하게 높인다 — 05_TestBattle 씬에서 버프 유무 A/B 대조로 검증.
- 가설 2: 모바일 세션(1회 5분 이하)에서도 핵심 루프(배치→전투→보상)를 완결할 수 있다 — `maddragon-mobile-loop` 워크트리 결과물로 세션 길이 측정 필요.
- 두 가설 모두 [제안]이며 현재 관측된 테스트 실행 결과(pass/fail)는 확인되지 않음.

## 11. 레퍼런스별 핵심 행동 단계 수와 적용 교훈

[제안] `MadDragon_레퍼런스_플레이예시_구버전.png` 파일 존재로 미루어 과거 레퍼런스 플레이 예시가 문서화된 적 있음이 확인되나, 내부 단계 수·구체 교훈은 이미지 파일 자체를 열람하지 못해 서술 불가. 향후 이미지 열람 후 단계별 행동 수(예: 배치→확인→전투 개시 등)를 구체화 필요.

[제안] 캐주얼 타워 디펜스 벤치마크의 핵심 행동은 유닛·타워 배치 → 전투 결과 확인 → 보상으로 강화의 3단계다. 적용 교훈은 버프 적용 범위와 강화 전후 효과를 배치 화면에서 비교 가능하게 만드는 것이다.

## 12. 수치 KPI와 측정 방법

- [제안 검증 목표] 첫 전투 완료까지 소요 시간 30초 이내 달성률 70% 이상 — 측정: 05_TestBattle 씬 진입~전투 종료 타임스탬프 로깅.
- [제안 검증 목표] 버프 건물 사용률(전체 배치 중 버프 건물 비중) 20% 이상 — 측정: 배치 이벤트 카운트 로그 집계.
- 실측 데이터는 현재 근거에 없으며 목표치는 모두 제안.

## 13. UI, HUD, 컨트롤

- [제안] 상태1 유닛 배치 선택 화면(팔레트 UI).
- [제안] 상태2 배치 확정 후 HUD(자원/타이머 표시).
- [제안] 상태3 전투 진행 중 HUD(체력바, 스킬 쿨다운).
- [제안] 상태4 승리 결과 화면(보상 목록).
- [제안] 상태5 패배/재시도 화면.
- `UI Toolkit` 폴더 존재만 [사실] 확인, 실제 화면 구성은 원문 미확인.

## 14. 로딩·빈 상태·에러·100개 이상 데이터·3배 긴 텍스트 대응

[제안] 현재 근거 자료에서 로딩 화면, 빈 상태(유닛 미배치), 에러 처리, 대량 데이터(적 웨이브 100개 이상), 긴 텍스트(다국어 스킬 설명) 대응에 대한 구체 구현 근거는 확인되지 않음. 향후 원문 및 UI 씬 확인 후 갱신 필요.

## 15. 접근성

[제안] 현재 접근성(색맹 대응, 텍스트 크기 조절, 터치 타깃 크기 등) 관련 구현 근거는 파일 목록에서 확인되지 않음. 모바일 루프 작업(`maddragon-mobile-loop`) 특성상 터치 타깃 크기 검토가 향후 필요.
